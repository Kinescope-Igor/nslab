Главные выводы

  1. DFN-3 — real-time везде. RTF < 0.2 на всех 14 успешных платформах, включая iPhone 13 (2021 г.) и macOS Ventura. Cold-frame 4-24 ms — приемлемо. Топ-1 кандидат для production Speak.
  2. macOS Sequoia + Chromium/Safari = top-tier. DFN-3 RTF 0.049-0.050 — в 20× запас. Все Win10/11 Chrome/Edge/Firefox: 0.082-0.103 (5-10× запас).
  3. macOS Ventura — деградация в 2-5×. Safari Ventura GTCRN RTF 0.469 vs Sequoia 0.093. Chrome Ventura DFN-3 0.111 vs Sequoia 0.049. Старые версии WebKit/Safari ML-WASM JIT слабее. Рекомендация: минимум macOS Sequoia для Mac-юзеров Speak.
  4. WebGPU не имеет смысла для NSLab-моделей. Pixel 8: RTF 13.2 vs WASM 0.238 (55× медленнее). Chrome macOS Sequoia: 1.217 vs 0.074 (16× медленнее). Chrome macOS Ventura: 3.266. Shader compile dominate — для tiny моделей это anti-optimization.
  5. iOS Safari + GTCRN OOM. onnxruntime-web default тянет JSEP-build (26 MB), iOS Safari не выделяет столько contiguous WASM heap на iPhone. wasmPaths-override на non-JSEP build не помогает — нужен правильный entry-point import (отдельная задача).
  6. Firefox macOS hangs. Таймаут > 360s. На Win 11 Firefox работает (DFN-3 RTF 0.082). Похоже специфика BrowserStack Firefox+macOS+ORT/TFLite WASM JIT.
  7. Edge ≈ Chrome на обеих OS (оба Chromium): идентичные RTF, идентичный webgpu anti-opt. Win10 ≈ Win11 для одного браузера (разница 5-10%).

Безопасный default для Speak команды

  • macOS Sequoia / любой современный браузер → DFN-3 (топ-качество, real-time).
  • macOS Ventura и старее → DFN-3 (тоже real-time, но GTCRN заметно деград'нет).
  • Win 10/11 любой Chromium/Firefox → DFN-3.
  • iOS Safari → DFN-3 (GTCRN не загружается из-за ORT-bundle).
  • Любая старая Android → RNNoise как fallback (минимальная нагрузка).
  • WebRTC NS — нулевой overhead, всегда работает как baseline на всех платформах.
