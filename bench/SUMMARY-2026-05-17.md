# NSLab — кросс-платформенный benchmark, 2026-05-17

URL: https://speak.kn.pe/lab/noise-bench/

Test signal: 10 sec pink noise + 1 kHz sine @ 48 kHz. Для 16 kHz моделей
resample 48→16 включён в per-frame latency.

Цвета RTF: <0.3 — большой запас; <1.0 — real-time на грани; ≥1.0 — не успевает.

## Главные выводы

1. **DFN-3 real-time везде** (RTF < 0.2 на всех 9 платформах, включая iPhone 13).
   Топ-1 кандидат для production. Cold-frame от 5 до 22 ms — приемлемо.

2. **GTCRN самый ультралёгкий**, p50 ≤ 5 ms почти везде, но **iOS Safari ловит
   OOM** при компиляции onnxruntime-web JSEP-build (26 MB). Устраняется
   переходом на non-JSEP entry-point ORT (отдельная задача — current
   wasmPaths-override не помогает, нужен правильный bundle import).

3. **WebGPU не имеет смысла** для NSLab-моделей:
   - Pixel 8: RTF 13.2 vs WASM 0.238 (в 55× медленнее)
   - Chrome macOS: RTF 1.214 vs WASM 0.074 (в 16× медленнее)
   - Shader compile overhead перевешивает выигрыш для маленьких моделей.

4. **Firefox быстрее на real Win11 чем в local Playwright Mac**:
   - BS Firefox Win11: DFN-3 RTF 0.092
   - Local Playwright Firefox Mac (Mac M-series): DFN-3 RTF 0.818
   - В 9× разница — вероятно bundled Playwright-Firefox без production
     оптимизаций. Production Firefox у пользователей работает нормально.

5. **Безопасный default для Speak команды**:
   - На desktop/Android — DFN-3 (топ-качество, real-time везде).
   - На iOS Safari — DFN-3 или RNNoise (GTCRN не загружается из-за ORT-bundle).
   - WebRTC NS как fallback для всех платформ — нулевой overhead.

## Известные нерешённые вопросы

- **iOS Safari + GTCRN OOM** — требует ORT non-JSEP bundle (`onnxruntime-web/wasm`
  alternative entry или manual webpack split).
- **Firefox macOS Playwright timeout 240s** — повторить с увеличенным timeout
  или поднять конкретное устройство для отладки.
- **Galaxy A52 osVersion 11.0** — не поддерживается на BS, нужен другой бюджетник
  (попробовать A53/A54/Galaxy M14).
- **Mem MB** — `performance.memory` работает только в Chromium, и delta JS-heap
  не отражает WASM-heap (часто 0.0 или negative из-за GC). Нужен другой подход
  (например performance.measureUserAgentSpecificMemory, требует COOP/COEP).
